Фронт взят из `dbarin` на коммите `05f27a0`, включая локализацию, адаптивные объекты, их карточки и разбор вкладов мероприятий. Сервер взят из `david` на коммите `bbc9c3a`. Интеграция находится в ветке `main`; исходники и тесты интерфейса размещены в `frontend/`.

## Автоматические проверки

Сначала запустите приложение командой из README. Проверки не обращаются к OpenAI.

```sh
docker compose run --rm --no-deps -v .:/workspace:ro -w /workspace/frontend ui node --test
docker compose run --rm --no-deps -v ./tests:/app/tests:ro api python -m unittest discover -s tests -p test_backend.py -v
docker compose run --rm --no-deps -v .:/workspace:ro -w /workspace ui node tests/parity.mjs http://ui:4173
```

Для локального Node.js из корня репозитория: `npm --prefix frontend test` и `npm --prefix frontend run test:parity`. Сервер интерфейса запускается командой `npm --prefix frontend start` и читает `.env.local` из корня репозитория. В контейнере интерфейс сохраняет рабочий каталог `/app` и получает переменные через Compose.

При работе с примонтированными Python-исходниками добавьте `-f compose.yaml -f compose.dev.yaml` перед `run`, чтобы тесты проверяли текущие файлы. Без dev-конфигурации используется собранный образ API: после правок пересоберите его.

JavaScript-тесты проверяют правила из каталога, адаптер форматов, переводы, размещение объектов на карте и HTTP-прокси. Python-тесты проверяют строгий контракт, контрольные расчёты, языки, резервные отчёты, ограничение параллельных AI-запросов и освобождение AI-слота после отключения клиента.

`tests/parity.mjs` обращается к работающему API. Он сравнивает каждый показатель района, итоговый Score, агрегаты и бюджет с браузерным предпросмотром. Включены оба пресета, наборы со всеми мероприятиями, лагами и синергиями, а также некорректные черновики. Граница ограничения значений 0–100 отдельно покрыта модульными тестами.

## Проверка через интерфейс

1. Выбрать M7, M8 и M10 для Нуры, M12 для города и M5 для Сарыарки. Бюджет 95, исходный Score 52.55768, итог 56.54307.
2. Переключить RU / ҚАЗ / EN. Выбор мероприятий и рассчитанные числа сохраняются, общий отчёт соответствует языку, районные выводы локализованы.
3. Проверить фокус и приближение района, сброс фокуса, раскрытие пульса, перетаскивание и предпросмотр.
4. Проверить возврат к карте, удаление меры и новый сценарий: старый результат не должен подменить текущий.
5. После расчёта сразу появляется обычный отчёт, без AI-запроса. Нажать «Получить рекомендации ИИ» для города или любого района. Во время генерации переключить язык или район: обычный отчёт доступен, предыдущий AI-запрос продолжает работу, новый автоматически не запускается. Вернуться в исходный район и язык: готовый ответ открывается из кеша по кнопке. Ответ содержит один короткий абзац; обычный отчёт доступен через кнопку возврата.
6. Проверить страницы длинного отчёта и отсутствие скролла всего виджета, включая короткое окно и мобильную ширину.

Без ключа и модели API возвращает `mode=fallback`, а интерфейс сохраняет обычный отчёт с сообщением и возможностью повторить запрос. Проверка живого AI требует локальных `OPENAI_API_KEY` и `OPENAI_MODEL` и отдельного перезапуска с `--env-file .env.local`; ключ не добавляется в Git.
