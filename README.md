# Виджет сценариев развития Астаны

Интерактивная карта, выбор мероприятий и отчёты по городу и районам. Интерфейс на HTML/CSS/JavaScript работает с FastAPI через один адрес. Python рассчитывает итоговые показатели; OpenAI формулирует объяснение уже рассчитанного результата. Числа в отчёте определяет расчётная модель, а не LLM.

## Запуск в Docker

Нужен Docker с Compose. Создайте `.env.local` из `.env.example`, если файла ещё нет. Для AI заполните **оба** поля `OPENAI_API_KEY` и `OPENAI_MODEL` своим ключом и доступным API ID модели. Значения модели по умолчанию нет. Пустые поля позволяют пользоваться расчётом и шаблонным объяснением.

```sh
docker compose --env-file .env.local up -d --build
```

Откройте [http://localhost:4173](http://localhost:4173). Остановка:

```sh
docker compose --env-file .env.local down
```

Compose запускает два сервиса:

| Сервис | Назначение | Доступ |
| --- | --- | --- |
| `ui` | Node.js отдаёт публичные файлы и проксирует `/api/*` | `127.0.0.1:4173` |
| `api` | FastAPI, датасет Tech2, расчёт и OpenAI | Только сеть Compose, порт 8000 |

UI запускается после готовности API. Ключ передаётся только контейнеру API; в браузер и UI-образ он не попадает. Статический сервер использует список разрешённых файлов, поэтому исходники API и файлы окружения через него недоступны. База данных, сохранение сценариев и авторизация не используются.

## Разработка

Для перезагрузки API и подключения исходников:

```sh
docker compose --env-file .env.local -f compose.yaml -f compose.dev.yaml up -d --build
```

Dev-конфигурация дополнительно открывает API на [http://localhost:8000](http://localhost:8000), документация доступна по [http://localhost:8000/docs](http://localhost:8000/docs). Изменения статики доступны при обновлении страницы. Node следит за серверным кодом, Uvicorn перезагружает Python.

Для запуска UI вне Docker нужен Node.js 22 или новее, npm-зависимостей нет. Сначала запустите только API:

```sh
docker compose --env-file .env.local -f compose.yaml -f compose.dev.yaml up -d --build api
node server.js
```

Если контейнер UI уже занял порт 4173, остановите его перед локальным Node:

```sh
docker compose --env-file .env.local stop ui
```

В Windows можно следить за всеми файлами проекта:

```sh
node --watch --watch-path=. server.js
```

Локальный Node читает необязательный `.env.local`. `API_URL` по умолчанию равен `http://127.0.0.1:8000`; внутри Compose используется `http://api:8000`. `API_PROXY_TIMEOUT_SECONDS=60` должен быть больше `OPENAI_TIMEOUT_SECONDS=45`. Лимит тела API-запроса — 16 КиБ. Прокси сохраняет статус и тело ответа API и передаёт ответ потоком; при недоступности API возвращает 502, при таймауте — 504.

Проверка JavaScript-модели, локализации и транспорта:

```sh
node --test
docker compose config --quiet
```

## Расчёт и AI

Каталог и правила загружаются через `GET /api/v1/catalog`. Черновик проверяется через `POST /api/v1/validate`, итог рассчитывается через `POST /api/v1/evaluate`. `POST /api/v1/explain` принимает сценарий и язык `ru`, `kk` или `en`, возвращает объяснение и режим `llm` либо `fallback`.

Отсутствие AI-конфигурации, ошибка или таймаут OpenAI приводят к явно обозначенному шаблонному объяснению; рассчитанные показатели сохраняются. Выбор модели задаётся только `OPENAI_MODEL`. Текущая настройка и результат последнего обращения видны в `GET /api/health/ai`; этот endpoint не делает внешний запрос и не проверяет текущую доступность OpenAI.

| Проверка через UI | Значение |
| --- | --- |
| `GET /health/live` | Node отвечает |
| `GET /api/health/live` | FastAPI отвечает |
| `GET /api/health/ready` | Датасет и базовый расчёт готовы |
| `GET /api/health/ai` | Конфигурация и последнее состояние AI |

Источник правил — `data/tech2-v1`. Браузерная модель служит для предварительного просмотра; итог подтверждает API. Индикаторы имеют шкалу 0–100, больше означает лучше; горизонт — 8 кварталов.

```text
Эффект меры = эффект из каталога × (8 − лаг) / 8
Балл района = Σ(вес индикатора × значение индикатора)
Средний балл = Σ(доля населения района × балл района)
Score = 0.7 × средний балл + 0.3 × минимальный балл района − N
```

`N` — количество значений ниже 40 во всех районах. Эффекты суммируются, затем применяются синергии; значения ограничиваются диапазоном 0–100.

- Ровно 5 разных мероприятий, бюджет до 100 условных единиц.
- Не более 2 мер одного направления; M1 и M3 несовместимы.
- M4 и M7, а также M5 и M13 нельзя сочетать в одном районе.
- Синергии: M1 + M2 дают +2 к T1, M10 + M12 дают +2 к B1, M5 + M6 дают +2 к E2 в районе локальной меры.

Базовый Score — **52.56**. Пресет `tech2-example`: M7, M8 и M10 в Нуре, M12 для города, M5 в Сарыарке. Стоимость **95 ед.**, итог **56.54**.

## Встраивание и языки

Разместите iframe в контейнере существующего сайта и замените `src` адресом UI:

```html
<div style="width: 100%; height: 820px;">
  <iframe
    src="http://localhost:4173/"
    title="Сценарии развития Астаны"
    style="display: block; width: 100%; height: 100%; border: 0;"
  ></iframe>
</div>
```

Переключатель RU / ҚАЗ / EN сохраняет язык и текущий сценарий. Переводы находятся в `locales.js`, форматирование — в `i18n.js`. Используются системные шрифты без внешних запросов.
